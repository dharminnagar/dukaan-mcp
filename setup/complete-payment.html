Why you are the one clicking this

The agent shopped, and the policy gate decided — that produced a real Razorpay Order (status: "created"). Nothing has been paid yet, because under current Indian payments regulation an agent cannot autonomously authorize a UPI payment. That authorization is a deliberate human step, not a missing feature.

Pasting the order id below, clicking Pay, and clicking through Razorpay's mock bank page with the test OTP is that step. Once it's done, the payment shows up under Transactions → Payments in the dashboard and the order stops being just a line under Orders.

2

Order id and key id

Both are public/publishable values — an order id identifies a specific order, a Key Id is the publishable half of a Razorpay API key pair.

Never paste the Key Secret here. This page has no field for it, needs no field for it, and cannot use it. Standard Checkout only ever needs the Key Id in the browser — the Key Secret belongs on a server, never in a page like this one.

The Key Id must start with rzp_test_. Razorpay's API base URL and the checkout script are identical for test and live mode — the key prefix is the only thing telling this page apart from one that could move real money. If it doesn't start with rzp_test_, the Pay button below stays disabled and checkout will refuse to open, exactly like the guard in scripts/smoke-razorpay.ts.

What happens next

Once the mock bank page confirms the payment, it appears in the Razorpay dashboard under Transactions → Payments (confirm the exact menu wording once you're in your own dashboard — it may have shifted). The order itself moves on from status: "created". Nothing on this page pushes that update anywhere else — checking the dashboard is a separate, manual step.

Test Mode only. No live keys, no Key Secret, no real money. The only network request this page makes besides Razorpay's own checkout flow is loading checkout.razorpay.com/v1/checkout.js.
