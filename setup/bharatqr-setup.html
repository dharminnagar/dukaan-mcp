Why this is still worth ten minutes

Be honest with yourself about the odds before you start, so you don't feel let down when nothing arrives.

This will almost certainly not land in time. Support review windows for this class of request are commonly cited as roughly two to three weeks. The submission deadline is approximately 5 September 2026 (per secondary sources — the official Buildathon page does not state it directly, so treat the date itself as reasonably firm but not primary-sourced). Raise both tickets today anyway, because lead time only starts once you submit — waiting a week to "do it properly" only shrinks the already-thin chance further.

The value here is narrative, not technical. The submission form has a "Build Challenges and Technical Obstacles" field. "I found the platform constraint, raised the documented request, and it did not clear in time" is a specific, verifiable answer almost nobody else submitting will have, because almost nobody else will have looked hard enough to hit this wall in the first place. The capability itself — actually getting S2S JSON v2 or BharatQR enabled — is a bonus on top of that, not the point.

Nothing in the build waits on either outcome. The payment loop already closes via a human-approved handoff — the agent shops, the policy gate decides, a real Order is created through POST /v1/orders, and a human completes authorization. That is the current legal shape under Indian payments regulation for an autonomous agent regardless of what these tickets come back with, so the pitch does not change if both are refused. If BharatQR is granted, the payment loop upgrades from a human-approved handoff to a headless simulated authorization via POST /v1/bharatqr/pay/test — a nicer demo, not a different architecture.

Ticket 1 — S2S JSON v2 on Test Mode

Why this one: a headless AI agent cannot complete authorization through Standard Checkout, because that flow requires a human to click through a mock bank page and enter an OTP in a browser. S2S JSON v2 is the documented server-to-server alternative — except it is gated behind this exact request.

Ticket 1 — S2S JSON v2 (copy this whole block)
Subject: Request to enable Server-to-Server (S2S) JSON v2 on Test Mode

Hi team,

I'm building an MCP server for the Razorpay AI Buildathon 2026 that exposes
buyer-side catalog and checkout tools to AI agents. It runs entirely on
Test Mode — no live traffic, no real money involved.

I'd like to request Server-to-Server (S2S) JSON v2 activation on my test
account. A headless AI agent cannot complete payment authorization through
Standard Checkout, since that flow requires a human to click through a
mock bank page and enter an OTP in a browser — there is no other
documented headless path to authorize a payment on a vanilla test account.

Could you enable S2S JSON v2 for Test Mode, or let me know what you need
from me to proceed? Happy to share more about the project if it helps.

Thanks,
Dharmin Nagar

S2S generally requires PCI-DSS certification, which a solo student project does not have. Expect a no — the value is in having asked and being able to say so, per Section 1.
