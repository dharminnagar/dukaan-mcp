# #0010 The metrics table is circular as designed and that makes it a liability rather than a differentiator. The same person writes the gate rules and the adversarial attacks, so the generator can only produce attacks the rule author already imagined. Precision and recall over that population measure implementation correctness against a spec, not detection capability against an adversary. A panel spots this fast. Two fixes: (1) relabel honestly as 'rule-coverage measurement over a declared threat model' and state the limitation in both README and video before a judge states it; (2) spend ~1.5hrs generating adversarial sessions from a SEPARATE Claude call whose context holds only the MCP tool schema and the merchant policy JSON, never the gate implementation — a genuinely different author, so any escape it finds is a real finding.
