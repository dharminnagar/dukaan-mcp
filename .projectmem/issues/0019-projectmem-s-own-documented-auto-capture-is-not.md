# #0019 projectmem's own documented auto-capture is NOT ACTIVE, and has never been. .projectmem/AI_INSTRUCTIONS.md carries a section headed 'Auto-Capture (active)' claiming git hooks installed by pjm init capture commits (post-commit), reverts (auto-classified as failed approaches), merges (milestones) and file churn, plus a 'Pre-commit safety net' section stating that 'Every git commit automatically runs pjm precheck against the staged files' and shows a warning block before the commit lands. Verified 2026-08-25: `ls .git/hooks/` contains ONLY .sample templates. No pre-commit, no post-commit, no hooks of any kind. `git config core.hooksPath` is unset. So none of that capture or safety-net behaviour has ever run in this repo. The git_commit field that does appear on events comes from the CLI reading HEAD at write time, not from a hook. CONSEQUENCES: (a) the pre-commit precheck that would have warned before touching a file with unresolved issues or recent failed attempts has never fired, which is part of why issue #0014's missing-scripts problem survived unnoticed; (b) reverts and merges are not being classified; (c) any agent trusting AI_INSTRUCTIONS.md believes a safety net exists that does not. FIX WITH A TRAP: husky is about to be installed for lint/format hooks, and husky sets core.hooksPath=.husky, which makes git ignore .git/hooks ENTIRELY. So running `projectmem hooks install` after husky would write hooks that silently never execute. The two must be reconciled deliberately: put the projectmem hook logic (pjm precheck on staged files pre-commit, commit capture post-commit) inside the .husky scripts rather than installing projectmem's own hooks, so one system does not quietly disable the other.
