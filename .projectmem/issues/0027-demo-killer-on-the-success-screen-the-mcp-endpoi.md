- 2026-08-26T16:37:01Z `fix`: #0027 FIXED and regression-guarded. Two servers were sharing one env var name: src/config.ts reads PORT for the MCP server (8787), but web/app/actions.ts also read process.env["PORT"] to build the endpoint string, and inside the Next process PORT is Next's own 3000. Verified by curl: POST http://127.0.0.1:3000/mcp returns 404, so the success screen's copy-paste endpoint was dead — the single artefact the entire onboarding flow exists to produce. Fix: read MCP_PORT (default 8787), never bare PORT, plus MCP_PUBLIC_URL which wins outright for a deployment behind a real hostname (DUK-25 needs that anyway). web/.env.example's PORT=8787 line was actively misleading in the web context and is now MCP_PORT with a comment saying why. GUARD: tests/web-onboard.test.ts asserts STATICALLY on the source text that actions.ts contains no process.env["PORT"] / process.env.PORT and does contain process.env["MCP_PORT"] — static because MCP_ENDPOINT is read at module load so a behavioural test would need a re-import with mutated env, and the trap is textual anyway. Mutation-proven: reintroducing the bug turns the suite red (13 pass 1 fail), restoring it green (14 pass 0 fail). Endpoint now renders http://127.0.0.1:8787/mcp, confirmed in the browser.
