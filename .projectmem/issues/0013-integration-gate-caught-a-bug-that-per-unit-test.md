# #0013 Integration gate caught a bug that per-unit test isolation had hidden. src/db/pool.ts exports ONE process-wide Pool singleton, and three test files (audit, policy, onboard) called closePool() in afterAll. Each unit passed running only its own named files, but the full suite went 42 pass / 11 fail: the first file to finish ended the pool and every later file died with 'Cannot use a pool after calling end on the pool'. Unit 4 hit this within its own two files, fixed it there and documented it, but the fix could not propagate because no unit owns another unit's files. Fixed centrally in commit 5b887ab by removing all three teardown calls; bun exits regardless. Now 58 pass / 0 fail, idempotent across reruns. LESSON: per-unit database isolation prevents data collisions but cannot catch process-level singleton collisions. The full-suite integration gate is not optional after a concurrent run.
