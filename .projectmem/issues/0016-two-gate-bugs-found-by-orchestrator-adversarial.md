# #0016 TWO GATE BUGS found by orchestrator adversarial probes against DUK-14, neither covered by the implementing agent's 10 tests. (1) DUPLICATE LINE ITEMS BYPASS THE STOCK CHECK. Check 1 validates `item.quantity > product.stock` per line item independently, so sending the SAME item_id twice with quantity 3 each against stock 4 passes both individual checks and the gate returns allow for 6 units of a 4-stock item. Probe: items=[{p1,qty3},{p1,qty3}], stock 4, cap and threshold set high so only check 1 could block -> decision=allow rule=ALLOW. This is a stock oversell on the exact check the ACP-alignment claim rests on, and it is adversarial in shape: budget-split evasion applied to stock within a single order rather than across orders. A merchant ships goods they do not have. (2) EMPTY ITEMS ARRAY IS ALLOWED. req.items=[] skips the check-1 loop, totals 0 paise, passes cap and threshold, and returns {decision:'allow', amount_paise:0}. The orders table would then reject it via CHECK (amount_paise > 0) and CONSTRAINT order_items_non_empty_array, so the gate approves something physically unstorable. This matters more than it looks because src/eval/ drives decide() DIRECTLY, bypassing any MCP-layer zod validation, so a malformed transcript yields a nonsensical allow that gets counted in the DUK-19 metrics.

- 2026-08-24T17:25:25Z `fix`: Both gate bugs fixed by the orchestrator in commit 13c1030, before the gate was ever committed, so the repo never carried the buggy version. Fix for bug 1: check 1 now validates asserted price PER LINE ITEM but stock PER AGGREGATE QUANTITY. Quantities are summed per item_id into a Map before the stock comparison, and the reported asserted_quantity is the aggregate rather than one line's share. A third hole surfaced while writing this fix and is also closed: naively deduping the catalog fetch would have deduped the PRICE check too, so the same item_id sent twice at two different asserted prices would only have the first validated and the agent would underpay on the rest. Hence two passes — price per line, stock per aggregate — and the module comment says why, because the split looks redundant to a reader who has not seen the attack. Fix for bug 2: an empty items array now returns INVALID_REQUEST with field 'items', audited under rule AUTHORITATIVE_REREAD because audit_events.rule has no INVALID_REQUEST member and adding one would need a migration for no behavioural gain. Three regression tests added to tests/gate.test.ts covering duplicate-stock oversell, duplicate-price underpay, and the empty basket. Also removed GateDeps.now: the implementing agent correctly reported it had no call site, because the cap window is enforced inside spentInWindowPaise's SQL against Postgres's own now(), so a clock passed from application code would be silently ignored — that was an orchestrator spec error, and an optional field that is silently ignored is exactly the foot-gun this codebase's style rules say to delete rather than document. Verified: 108 pass / 0 fail across 11 files on two consecutive runs, typecheck exit 0, and both original probes now return block. [src/gate/index.ts]
